### 别人帖子下的引流评论（找相关问题回答）

**场景：知乎问题“Jetson Orin 上怎么做 INT8 量化？”**
```
我这边的结论是：Orin 上最重要的不是“几 bit”，而是“覆盖率”和“数据流”。只把一小块 Linear 打成 INT8，端到端可能几乎没变化；把 MoE expert 和前后短链一起收进去，收益才会真正释放。
```

**场景：知乎问题“INT8 为什么有时反而慢？”**
```
因为朴素 INT8 很容易把 dequant、INT32 回写和 launch overhead 一起带出来。真正要看的是有没有把 dequant 融进 epilogue，把中间结果留在寄存器里。
```

**场景：知乎问题“TensorRT 还是自定义 runtime？”**
```
对 wall-x 这种自定义算子和动态图都很多的模型，先把热路径 Linear 的 QDQ island 手工打通更现实；后面再把这些边界抽成图级 pattern，让后端去做 fusion 和 lowering。
```

### 别人帖子下的引流评论

**场景：Jetson Orin / 端侧部署帖子**
```
Orin 上做量化，最容易踩的坑不是位宽，而是数据流没一起改。只把 Linear 打成 INT8 不够，后面的小链路不收，端到端照样不快。
```

**场景：大模型优化帖子**
```
量化到后面，已经不是“换格式”了，而是在逼 runtime。QDQ、fusion、CUDA Graph 这些东西，最后都会回到同一个问题：数据怎么流得更短。
```

**场景：机器人 / 具身智能帖子**
```
做端侧 VLA 的最大感受是：模型当然重要，但真正决定能不能上机器人，最后还是 runtime。我们这篇就是在把这条路往量化框架的方向往前推。
```
